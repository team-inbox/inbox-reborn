# Gmail selector audit — July 2026

Cross-reference of every Gmail DOM hook in `src/script.js` / `src/style.css` against
actively maintained Gmail-integrating projects (InboxSDK, FlowCrypt, gmail.js, Simplify,
Gmail userstyle repos) and 2026 breakage reports. Regenerate when Gmail next shifts;
run `docs/selector-health-check.js` in DevTools for live ground truth.

## Headline

No single 2026 event renamed everything — Gmail is incrementally migrating surfaces to Wiz build-hashed classes with a concrete change cluster in Nov 2025 and June 2026 that lands squarely on this extension's hooks. Highest-confidence breakage: (1) the right side panel is being restructured right now (InboxSDK's identical selectors began failing 2026-06-15; consumer Gemini-panel removal Jan 2026) — the floating compose/reminder button positioning (.bse-bvF-I.aT5-aOt-I, .buW, .br3, #qJTzr) is almost certainly glitching; (2) the reply pill bar and 3-dot menu were rebuilt with Wiz tokens (.aaq/.ams -> .btDi4d/.DILLkc, .aap -> .Wsq5Cf, .J-M -> new menu classes per FlowCrypt and three corroborating projects) — dark-mode reading-pane pills/buttons render unthemed on the new markup; (3) compose chrome changed in June 2026 (titlebar icons now keyed off .Ht, which appears nowhere in style.css, plus a rolling compose-actions relayout) — dark-mode compose glitches expected; (4) the May 2026 logo rebrand endangers the positional a[aria-label='Gmail'][1] header-retitle hook. Meanwhile the core threadlist anatomy (tr.zA, .y6, td.a4W, .xW span[title], span[email]) is independently verified still current mid-2026, so date headers, bundling, reminders, avatars and calendar cards are probably intact — the visual glitches Joey sees are concentrated in dark mode and the FABs. Because everything runs on a silent 250ms polling loop, breaks never error. Do first: run the diagnostic checklist in DevTools on a live inbox, apply the small additive fixes (new Wiz tokens in CSS, side-panel re-anchor to [role='complementary']/div.aUx), then invest in the selector registry with dated fallback chains plus runtime health logging so the next Gmail push is a one-line fix instead of a hunt.

## Hardening roadmap

### 1. Ship a runtime selector health-check with logging (do this first) (small)

The main pipeline is setInterval(updateReminders, 250) with no error path, waitForElement gives up silently after 10s, and reorderMenuItems retries forever — every selector break manifests as silent feature absence. Add a small module that runs the diagnostic checklist (this audit's diagnosticSelectors) once after load and on demand from the options page, console.warn's any 0-match critical selector, and persists failures to chrome.storage so you can see exactly which hook died after a Gmail push. Also bound the reorderMenuItems retry loop (e.g. give up after 40 tries) while you're in there.

### 2. Re-anchor the side-panel/FAB feature immediately (highest active churn) (medium)

Gmail is changing the right side panel right now (InboxSDK telemetry commit 79b97a2, 2026-06-15; consumer Gemini-panel removal Jan 2026). Replace 'div[aria-label="Side panel"]' + '.bse-bvF-I.aT5-aOt-I:not(#qJTzr)' + '.buW'/'.br3' in script.js 1688-1731/1900 with: scope = div[role='complementary'][aria-label='Side panel'] (fallback div.aUx), buttons = [role='button']/[role='tab'] children, collapsed-state = measured width from a ResizeObserver on the region. Degrade to a fixed FAB position when nothing matches instead of silently never positioning.

### 3. Add the new Wiz tokens additively to the dark-mode CSS (small)

Three concrete renames are documented by peer projects: reply pills .aaq/.ams -> .btDi4d/.DILLkc/.jWOS7-JX-I (FlowCrypt Nov 2025 + 3 corroborating repos), 3-dot button .aap -> .Wsq5Cf, menu container .J-M -> ul.aqdrmf-Kf[role='menu']/.tB5Jxf-M-S5Cmsd. Append the new tokens to the existing rules at style.css 3472-3478, 3721, 3860-3861, 2064, 2962-3005 and keep the old ones as dated fallbacks (InboxSDK's selector_YYYY_MM_DD pattern: never delete a working selector, chain it).

### 4. Build a central selector registry with dated fallback chains (large)

script.js already half-does this (the SELECTORS-ish constants around lines 163-207); finish the job: one module mapping semantic names ('threadRow', 'dateCell', 'sidePanel', ...) to ordered arrays of selectors with a dated comment per entry, resolved by first-match. Every querySelector in the file goes through it. This is what lets InboxSDK survive quarterly churn — a break becomes a one-line registry addition instead of an archaeology dig across 5,900 lines of CSS and 1,900 of JS.

### 5. Re-anchor feature-critical queries to stable attributes (medium)

Adopt the anchors every maintained project converged on: [gh='tl'] (thread list — replaces the .nH.ar4.z hide-rule scope), [gh='tm']/[gh='mtb'] (toolbars — co-anchor the .D.E.G-atb dark rules), [gh='cm'] (compose button — replaces .T-I.T-I-KE.L3 and backs up .Yh.akV), header[role='banner'] a[aria-label='Gmail'] with count assertion (replaces the positional [1] index at script.js:180), form[role='search'], div[role='textbox'][g_editable='true'] (backs up div[aria-label='Message Body']), textarea[name='to'] (backs up peoplekit-id='BbVjBd'). Keep obfuscated classes as secondary refinement, never as the sole anchor.

### 6. Use invert-filter for whole rebuilt surfaces instead of per-class styling (medium)

Your own memory notes invert-filter beats per-class styling for Gmail compose, and the .nH.Hd[role='dialog'] invert is the extension's most churn-resistant dark-mode block. Apply the same approach to the theme-picker dialog (delete the four contradictory .uW2Fw-bHo passes, style.css 5108-5417), Quick Settings (.IU, three 'final attempt' passes), and the compose titlebar (which needs re-auditing anyway for the June 2026 .Ht change). This also automatically covers Gmail's new unthemed AI Overview cards (Simplify #879) without knowing their classes.

### 7. Stop building extension UI out of Gmail's classes (large)

Generated bundle rows and calendar cards are assembled from Gmail classes (div.zA.yO, span.oZ-x3.xY, .yX, .y2, .brc/.brd/.brg/.bzB — script.js 744-751, 851-881, including a dead literal '.yW' at 747), so a Gmail CSS rename silently unstyles the extension's own UI even while its selectors still match. Give every generated node an extension-owned class and own CSS mirroring the needed row styles; keep the Gmail classes only as progressive enhancement. Also replace the injected '.nH.ar4.z [id=...]' hide rules with a JS-set attribute (row.dataset.irHidden) plus one own CSS rule.

### 8. Eliminate positional and structural landmines (small)

Fix the known worst offenders: '.wT > .n3 .byl:first-child .aim:first-child .nZ' (720/3641/4758 — breaks on the extension's OWN menu reordering), '.aBA + .bkK > .nH > .ar4 > div' (176), '.nH.bkK.nn + .nH.nn' (2449/3633/5470), 'div:nth-child(n+3) > img' (2270/2274), className.indexOf('zE') -> classList.contains('zE') (script.js 470), and previousSibling.className === 'time-row' exact-equality. Gmail spent H1 2026 inserting hidden dialogs and AI nodes into existing containers (Simplify #894), which is exactly what kills sibling/nth-child chains.

### 9. Deduplicate the CSS and delete dead rules (medium)

The icon blocks are triplicated (chrome-extension:// + two @-moz-document blocks) and the dark surface dumps are duplicated verbatim (2903-2934 vs 3565-3641) — every Gmail rename must currently be fixed in 2-3 places. Since Firefox is explicitly low priority, generate the moz-extension:// copies with a tiny build step (or drop them). Delete confirmed dead code: '.body.dark-mode' typo rules (4763-4764), 'body.dark .Hp' (3217), '.J-Ke.n4.ah9' (script.js 172), the write-only menuNodes map, and the literal '.yW' class token (script.js 747).

### 10. Replace inline-style value matching with computed values (small)

[style='color: rgb(225, 227, 225)'] (2519), [style*='background-color: rgb(225, 227, 225)'] (2589) and getBundleTitleColorForLabel's hard-coded 'rgb(221, 221, 221)'/'rgb(225, 227, 225)' comparisons depend on exact serialization and Gmail's current default palette — a palette tweak reintroduces the near-white bundle-title bug. Read getComputedStyle in JS once per label, decide there, and write an own data-attribute the CSS keys on.

### 11. Gate locale-dependent text hooks (medium)

[data-tooltip='Inbox'/'Social'/...], innerText === 'RSVP', ariaLabel !== 'Not starred', aria-label^='Google Account: ', aria-label^='Get ', and :has(.at[title='Inbox']) all silently die on non-English Gmail. Minimum: check document.documentElement.lang at startup and log/badge a warning that bundling/reminders/icons need en; better: pair each with a structural or class fallback so English text is a refinement, not the anchor.

### 12. Centralize URL-hash routing assumptions (small)

isInBundle()'s regex on '#search/in%3Ainbox+label%3A', handleHashChange's '#category/...'/'#label/...'/'#settings/labels' mapping, bundle navigation writing location.href, and the CSS [href='#inbox'...] title rules all encode Gmail's current hash scheme. Extract one route helper (parseGmailHash/buildLabelSearchHash) so a Gmail routing change is a single-function fix, and have the health check assert the current hash parses.
